## Задача 3

Выберите подходящую систему управления виртуализацией для предложенного сценария. Опишите ваш выбор.

Сценарии:

1. 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
   Система: Xen.
   Выбор обусловлен поддержкой как Linux так и Windows систем. Более гибкое и стабильное решение, особенно для Linux.

2. Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
   Система: Xen.
   Выбор обусловлен: open-source решение, универсальное, гибкое.

3. Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
   Система: Hyper-V
   Выбор обусловлен: нативное Windows решение, бесплатное.

4. Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux
   Система: KVM
   Выбор обусловлен: нативное решение для Linux, стабильность.

## Задача 4

Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?

Возможные проблемы:

- сложная система поддержки. Или администраторы должны знать несколько платформ или нужно несколько администраторов.
- нет централизованного контроля
- сложно обеспечить резервное копирование
- сложный перенос между ВМ разными системами
- риски ИБ, т.к. больше точек администрирования - больше вероятность ошибок

Что сделать для минимизации рисков и проблем:

- настроить мониторинг, логирование и резервное копирование для всех платформ по единым правилам
- постараться ограничить число платформ до минимума
- ввести единый центр управления
- установить жесткий контроль доступа к административным интерфейсам

Если бы у меня был выбор, я бы постарался не создавать такую систему. Я бы применил универсальную систему (xen или proxmox), если на этапе планирования была бы неопределенность в платформах.
